# 7. Report results

**You do:** tell the agent how the print went, in your own words.
**The agent does:** records it as you said it, and turns problems into the next revision.

## What to say

Anything you noticed is useful. Helpful details:

- Did each part print cleanly? Corners lifting, stringing, rough patches,
  a failed bridge?
- How did each fit feel: loose, right or tight? Which direction was anything off?
- Did assembly go as `PRINT.md` said?
- How does it work in use, now and after a few days?
- A photo of anything that looks wrong. Save it in the project's
  `reference/` folder and tell the agent the file name.

"It all worked" is a great report too.

## Where it goes

- Your words go into the project's `observations.md`, quoted, with the date.
  That file only grows; nothing is rewritten.
- Under your report, the agent notes what it shows and what is still unknown.
- A one-line result goes at the end of `PRINT.md`.
- If something needs to change, the agent makes a new revision (v2), with
  new files. Your v1 files stay as they were.
- `status.md` and [PROJECT_STATE.md](../PROJECT_STATE.md) are updated. A
  finished project is marked finished.

## Why bother

Your report is the only real evidence that the design works. The checks
only show that the model looks right. A good report also teaches your printer's
fits for next time: they go in [my-printer.md](../my-printer.md), so the next
project starts closer.

## In the example

The author's report after printing: *"Fully printed and constructed without
issues! It all came together seamlessly."* See how it was recorded in
[observations.md](../examples/keypad-sculpture/observations.md), including
what was **not** reported yet: whether the door magnets hold over time.
